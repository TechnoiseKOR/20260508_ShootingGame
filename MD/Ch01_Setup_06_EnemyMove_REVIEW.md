# Ch01_Setup_06_EnemyMove_REVIEW

## 리뷰 대상

이번 리뷰 대상은 적 생성 및 이동 구현 패치다.

패치 요약:

- 기본 씬에 `Enemy` 오브젝트 추가
- `Assets/Scripts/Enemy.cs` 추가
- `Enemy` 오브젝트에 `Enemy` 스크립트 연결
- 적이 아래쪽으로 이동하도록 구현

## 전체 평가

이번 작업은 총알 발사 이후 다음 단계로 적절하다.

아직 적 자동 생성이나 충돌 처리는 없지만,
적이 어떤 오브젝트이고 어떻게 움직이는지 먼저 확인할 수 있다.

초급자에게는 “적 생성, 이동, 충돌, 점수”를 한 번에 구현하는 것보다,
먼저 “적 자체가 아래로 움직인다”를 확인하는 방식이 이해하기 쉽다.

## 좋은 점

### 1. 기능 범위가 작다

이번 단계에서는 적 이동만 구현했다.

다음 기능을 미리 만들지 않고,
적 오브젝트와 적 이동 스크립트에 집중한 점이 좋다.

### 2. 총알 이동 코드와 비교하기 쉽다

이전 총알 이동 단계에서는 `Vector3.up`을 사용했다.

이번 적 이동 단계에서는 `Vector3.down`을 사용한다.

```csharp
Vector3 dir = Vector3.down;
```

이 비교를 통해 학생들은 방향 벡터의 의미를 쉽게 이해할 수 있다.

### 3. 오브젝트와 스크립트 연결 흐름이 반복된다

이전 단계들에서 다음 흐름을 반복했다.

- `Player`에 `PlayerMove` 붙이기
- `Bullet`에 `Bullet` 붙이기
- `Player`에 `PlayerFire` 붙이기
- `Enemy`에 `Enemy` 붙이기

반복되는 구조라서 Unity의 기본 작업 흐름을 익히기 좋다.

### 4. Inspector에서 속도를 확인할 수 있다

`speed` 값이 Inspector에 보일 수 있는 구조라서,
학생들이 값을 바꿔보며 적 속도 변화를 바로 확인할 수 있다.

## 확인이 필요한 점

### 1. Play 모드에서 적 이동 확인

Unity에서 Play 모드로 실행한 뒤 아래 내용을 확인한다.

- Enemy가 아래쪽으로 이동하는지
- 속도가 너무 빠르거나 느리지 않은지
- 카메라 화면에서 이동이 잘 보이는지

### 2. 적 위치 확인

현재 Enemy는 `{x: 0, y: 4, z: 0}` 위치에 배치되어 있다.

확인할 내용:

- 화면 위쪽에서 시작하는지
- Player와 구분되어 보이는지
- 아래로 내려오는 움직임이 확인되는지

### 3. 화면 밖으로 나가는 적

현재 적은 화면 밖으로 나가도 제거되지 않는다.

지금 단계에서는 문제가 아니지만,
나중에 적을 계속 생성하게 되면 반드시 정리해야 한다.

## 개선하면 좋은 점

### 1. 빈 Start 메서드 정리

현재 `Start()`는 비어 있다.

수업 초반에는 그대로 둬도 되지만,
나중에 사용하지 않는 메서드는 삭제하는 것이 좋다.

### 2. public 필드 정리

현재 `speed`는 public 필드다.

초급 단계에서는 괜찮지만,
나중에 코드 스타일을 정리할 때는 `[SerializeField] private`로 바꾸는 것이 좋다.

### 3. 적 삭제 처리

나중에 적 자동 생성 기능을 만들면,
화면 밖으로 내려간 적을 삭제해야 한다.

가능한 다음 단계:

- 일정 시간이 지나면 삭제
- 특정 y 위치보다 아래로 내려가면 삭제
- DestroyZone에 닿으면 삭제

### 4. 적 프리팹화

현재 적은 씬에 직접 배치되어 있다.

나중에 적을 여러 번 생성하려면 `Enemy`도 프리팹으로 만드는 것이 좋다.

다만 지금 단계에서는 적 이동을 먼저 확인하는 것이 우선이므로 현재 구조도 적절하다.

## 다음 단계 제안

다음 단계는 충돌 처리 또는 적 프리팹화 중 하나로 갈 수 있다.

### 선택 2. 적 프리팹과 자동 생성

내용:

먼저 총알과 적 충돌을 확인하는 방향도 자연스럽다.

## 최종 결론

이번 패치는 적 이동 기능을 이해하기 좋은 단계다.

총알은 위로 이동하고,
적은 아래로 이동하는 기본 슈팅 게임 구조가 만들어졌다.

다음 단계에서는 총알과 적이 만났을 때 사라지는 충돌 처리를 추가하면 좋다.
