# Ch01_Setup_03_PlayerMove_REVIEW

## 리뷰 대상

이번 리뷰 대상은 플레이어 이동 구현 패치다.

패치 요약:

- `Assets/Scripts` 폴더 추가
- `Assets/Scripts/PlayerMove.cs` 추가
- 기본 씬에 `Player` 오브젝트 추가
- `Player` 오브젝트에 `PlayerMove` 스크립트 연결

## 전체 평가

이번 작업은 첫 실제 게임 기능 구현 단계로 적절하다.

아직 총알, 적, 점수 같은 기능을 만들지 않고
플레이어 이동만 구현했기 때문에 수업 흐름에 잘 맞는다.

## 좋은 점

### 1. 기능 범위가 작다

이번 단계에서는 플레이어 이동만 구현했다.

이 방식은 초급자가 Unity의 기본 흐름을 이해하기 좋다.

- 오브젝트 만들기
- 스크립트 만들기
- 스크립트 붙이기
- Play 모드에서 확인하기

위 흐름을 한 번에 경험할 수 있다.

### 2. 코드가 이해하기 쉽다

`Input.GetAxis`로 입력을 받고,
`transform.position`을 직접 바꾸는 구조라서 초반 수업에 적합하다.

복잡한 물리 이동이나 고급 구조를 사용하지 않은 점이 좋다.

### 3. 이동 속도를 조절할 수 있다

`speed` 값이 Inspector에 보일 수 있는 구조라서
학생들이 값을 바꿔보면서 이동 속도 변화를 확인하기 쉽다.

### 4. 필요한 폴더만 생성했다

이번 기능에 필요한 `Assets/Scripts` 폴더만 생성되었다.

이전 AGENTS 지침의 “필요한 파일과 폴더는 해당 기능을 구현할 때 생성한다”는 방향과 잘 맞는다.

## 확인이 필요한 점

### 1. Play 모드 이동 확인

Unity에서 Play 모드로 실행한 뒤 아래 입력을 확인한다.

- 방향키
- WASD

확인할 내용:

- Player가 좌우로 움직이는지
- Player가 위아래로 움직이는지
- 이동 속도가 너무 빠르거나 느리지 않은지

### 2. 이동 축 확인

현재 코드는 다음 방향으로 이동한다.

```csharp
Vector3 dir = new Vector3(h, v, 0.0f);
```

즉, X/Y 평면에서 움직인다.

카메라가 정면에서 바라보는 2D 슈팅 화면이라면 이 방식이 자연스럽다.

만약 이후 수업에서 바닥이 있는 3D 공간처럼 사용한다면,
그때는 X/Z 평면 이동으로 바꿀 수 있다.

### 3. 화면 밖 이동 제한

현재는 이동 제한이 없기 때문에 Player가 화면 밖으로 나갈 수 있다.

다음 단계에서 화면 경계 제한을 추가하면 좋다.

## 개선하면 좋은 점

### 1. 빈 Start 메서드 정리

현재 `Start()`는 비어 있다.

수업 초반에는 Unity 기본 스크립트 구조를 보여주는 의미가 있지만,
나중에는 사용하지 않는 메서드를 삭제해도 된다.

### 2. public 필드 정리

현재 `speed`는 public 필드다.

초급 단계에서는 괜찮지만,
프로젝트가 조금 더 정리되면 `[SerializeField] private`로 바꾸는 것이 좋다.

예:

```csharp
[SerializeField] private float speed = 5.0f;
```

### 3. 대각선 이동 속도

현재 방식은 대각선 입력 시 이동 방향 벡터의 길이가 커질 수 있다.

나중에 이동을 더 정확하게 만들고 싶다면 다음처럼 정규화할 수 있다.

```csharp
Vector3 dir = new Vector3(h, v, 0.0f).normalized;
```

다만 초반 수업에서는 현재 코드가 더 이해하기 쉽다.
