# Ch01_Setup_01_AGENTS_ProjectGuideline_REVIEW

## 리뷰 대상

이번 리뷰 대상은 `ShootingGame` 프로젝트의 `AGENTS.md`에 프로젝트 전용 추가 지침을 넣는 작업이다.

기본 `AGENTS.md`는 이미 다음 기준으로 생성되어 있다.

```text
/init AGENTS.md for Unity 6.4 3D 프로젝트 한글로
```

## 전체 평가

이번 방향은 적절하다.

기본 `AGENTS.md`가 이미 Unity 6.4, URP, 3D 물리, 파일 관리, 테스트, 응답 방식 등을 정리하고 있기 때문에
처음부터 문서를 다시 작성할 필요가 없다.

이번 단계에서는 문서 하단에 수업용 슈팅 게임 제작 흐름에 필요한 최소 추가 지침만 넣는 것이 좋다.

## 좋은 점

### 1. 프로젝트명이 더 안전해졌다

이전 `Shooting2D`라는 이름은 Codex가 일반적인 Unity 2D 프로젝트로 해석할 가능성이 있었다.

이번에는 프로젝트명을 `ShootingGame`으로 잡았기 때문에
특정 물리 방식으로 과하게 끌려갈 가능성이 줄었다.

### 2. 기본 AGENTS.md가 3D 프로젝트 기준으로 생성되었다

현재 기본 문서에는 3D 프로젝트 기준이 명확하게 들어가 있다.

특히 다음 내용이 이번 프로젝트와 잘 맞는다.

- Unity 6.4 계열 3D 프로젝트
- 3D 물리는 `Rigidbody`, `Collider`, `Physics` 기준
- 2D 물리 API와 혼용하지 않음

이전보다 프로젝트 방향과 기본 지침의 충돌이 적다.

### 3. 추가 지침이 과하지 않다

이번 추가 지침은 구체적인 구현 순서나 API 예시를 많이 넣지 않는다.

대신 다음과 같은 프로젝트 진행 원칙에 집중한다.

- 작은 기능 단위로 구현
- 필요한 것만 만들기
- 미리 폴더나 파일 만들지 않기
- 초보자도 따라갈 수 있는 코드 작성
- Unity Editor 설정을 따로 안내

이 정도가 수업 초반 AGENTS.md 추가 지침으로 적절하다.

### 4. 학생용 프롬프트로 사용하기 쉽다

프롬프트가 너무 기술적으로 복잡하지 않다.

학생들은 Unity의 세부 API를 모두 이해하지 못해도,
Codex CLI에 붙여넣어 작업을 진행할 수 있다.

## 주의할 점

### 1. 기본 AGENTS.md의 Input System 기준

현재 기본 `AGENTS.md`에는 새 기능은 Input System 기반으로 작성한다는 내용이 있다.

수업에서 Legacy Input 또는 Unity 기본 `Input` 방식을 사용할 예정이라면,
첫 실제 구현 프롬프트에서 입력 기준을 명확히 적어주는 것이 좋다.

예:

```text
이번 기능에서는 Unity 기본 Input 방식을 사용해줘.
```

다만 이번 단계에서는 기본 `AGENTS.md`를 과하게 수정하지 않는 것이 목표이므로,
입력 방식은 실제 플레이어 이동 단계에서 정리해도 된다.

### 2. 구현 순서는 아직 넣지 않는다

이번 추가 지침에는 구체적인 구현 순서를 넣지 않는 것이 좋다.

플레이어, 총알, 적, 점수, 게임 오버 같은 전체 순서를 미리 적으면
학생이 아직 배우지 않은 내용을 먼저 보는 느낌이 될 수 있다.

구현 순서는 각 차시 프롬프트에서 하나씩 제시하는 편이 좋다.

### 3. 폴더 이름 예시는 아직 넣지 않는다

`Assets/Scripts`, `Assets/Prefabs` 같은 폴더 이름을 미리 적으면
Codex가 해당 폴더를 먼저 만들 가능성이 생길 수 있다.

이번 기준에서는 "필요할 때 생성한다" 정도만 두는 것이 적절하다.

## 수정 필요 여부

현재 프롬프트 방향은 그대로 사용해도 된다.

다만 실제 수업 진행 시에는 다음 원칙을 유지하면 좋다.

```text
AGENTS.md 기준으로 작업해줘.
이번 단계에서 필요한 것만 만들어줘.
요청한 부분 이외의 작업은 하지 마.
```

## 다음 단계 제안

이번 작업이 끝나면 다음 단계부터 실제 게임 기능을 하나씩 구현하면 된다.

다음 3종셋은 예를 들어 아래처럼 만들 수 있다.

```text
Ch01_Setup_02_PlayerObject.md
Ch01_Setup_02_PlayerObject_CHANGE_ANALYSIS.md
Ch01_Setup_02_PlayerObject_REVIEW.md
```

또는 바로 이동 기능부터 시작한다면:

```text
Ch01_Setup_02_PlayerMove.md
Ch01_Setup_02_PlayerMove_CHANGE_ANALYSIS.md
Ch01_Setup_02_PlayerMove_REVIEW.md
```

## 최종 결론

`ShootingGame`으로 프로젝트를 다시 만든 것은 좋은 선택이다.

기본 `AGENTS.md`가 3D 프로젝트 기준으로 생성되었기 때문에
이번에는 기존 문서를 크게 수정하지 않고,
하단에 프로젝트 전용 추가 지침만 넣는 방식이 가장 깔끔하다.

앞으로도 언리얼 TPS 프로젝트 때처럼 아래 3종 구조를 유지하면 된다.

```text
작업명.md
작업명_CHANGE_ANALYSIS.md
작업명_REVIEW.md
```
