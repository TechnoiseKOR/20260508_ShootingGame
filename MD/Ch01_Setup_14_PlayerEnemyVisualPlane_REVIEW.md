# Ch01_Setup_14_PlayerEnemyVisualPlane_REVIEW

## 리뷰 대상

이번 리뷰 대상은 Player와 Enemy 외형 변경 패치다.

패치 요약:

- `.gitignore`에 Unity 복구 폴더 제외 추가
- Player의 기본 큐브 외형 제거
- Player 아래에 `Plane1` 비행기 외형 추가
- Enemy 프리팹의 기본 큐브 외형 제거
- Enemy 프리팹 아래에 `Plane2` 비행기 외형 추가
- Player 위치를 화면 아래쪽으로 이동
- 기존 스크립트와 충돌 컴포넌트는 유지

## 전체 평가

이번 작업은 에셋 import 이후 자연스러운 외형 교체 단계다.

기존 게임은 기능은 동작하지만 Player와 Enemy가 기본 큐브처럼 보였다.  
이번 변경으로 Player와 Enemy가 비행기처럼 보이게 되어 게임 느낌이 훨씬 좋아진다.

중요한 점은 외형만 바꾸고 기존 로직은 유지했다는 것이다.  
수업용 프로젝트에서는 이 방식이 안전하고 이해하기 쉽다.

## 좋은 점

### 1. 기능과 외형이 분리되어 있다

Player와 Enemy 부모 오브젝트는 기존 기능을 유지한다.

부모 오브젝트가 담당하는 것:

- 이동
- 발사
- 충돌
- 레이어
- Collider
- Rigidbody

자식 비행기 프리팹이 담당하는 것:

- 화면에 보이는 외형

이렇게 분리하면 외형을 바꿔도 게임 로직이 크게 흔들리지 않는다.

### 2. 기존 스크립트를 수정하지 않았다

이번 패치에서는 C# 코드가 바뀌지 않았다.

즉, 외형 변경 때문에 이동, 발사, 충돌 로직이 복잡해지지 않았다.

### 3. Enemy 프리팹에 외형을 적용했다

Enemy는 EnemyManager가 계속 생성하는 오브젝트다.

따라서 씬에 있는 Enemy 하나만 바꾸는 것이 아니라, Enemy 프리팹 자체에 Plane2 외형을 넣은 것이 적절하다.

이제 새로 생성되는 Enemy도 비행기 외형을 가진다.

### 4. Player 위치가 슈팅 게임 화면에 맞게 조정되었다

Player가 y `-4` 위치로 이동했다.

슈팅 게임에서는 플레이어가 화면 아래쪽에 있는 것이 자연스럽기 때문에 적절한 변경이다.

### 5. Unity 복구 폴더가 제외되었다

`.gitignore`에 `Assets/_Recovery/`와 `Assets/_Recovery.meta`가 추가되었다.

Unity 작업 중 생기는 복구 폴더가 실수로 커밋되지 않도록 한 점이 좋다.

## 확인이 필요한 점

### 1. Play 모드에서 기존 기능 확인

외형을 바꿨더라도 기존 기능이 그대로 동작해야 한다.

확인할 내용:

- Player가 이동하는지
- Player가 총알을 발사하는지
- Enemy가 생성되는지
- Enemy가 이동하는지
- Bullet과 Enemy 충돌이 동작하는지
- DestroyZone 삭제가 동작하는지

### 2. Player 외형 방향 확인

Player의 자식 Plane1은 회전값이 조정되어 있다.

Play 모드에서 비행기 앞쪽이 의도한 방향을 향하는지 확인해야 한다.

총알이 나가는 방향과 비행기 방향이 어긋나면 회전값을 다시 조정해야 한다.

### 3. Enemy 외형 방향 확인

Enemy 프리팹의 자식 Plane2는 y축 180도 회전이 적용되어 있다.

Enemy가 화면 위에서 내려올 때 비행기 방향이 자연스러운지 확인해야 한다.

### 4. 충돌 박스 확인

Player와 Enemy는 기존 BoxCollider를 유지한다.

비행기 외형과 충돌 박스가 너무 다르면 실제 충돌 느낌이 어색할 수 있다.

수업 중에는 Scene View에서 Collider 표시를 켜고 확인하면 좋다.

## 개선하면 좋은 점

### 1. Collider 크기 보정

비행기 외형에 맞게 BoxCollider 크기를 조금 조정하면 충돌 느낌이 좋아진다.

다만 이번 단계에서는 외형 교체만 목표이므로, 다음 단계에서 별도로 진행해도 된다.

### 2. Bullet 외형 교체

Player와 Enemy가 비행기 외형이 되었으므로, 총알도 조금 더 작고 명확한 외형으로 바꾸면 좋다.

다음 단계 후보:

```text
Ch01_Setup_15_BulletVisual
```

### 3. Plane 자식 이름 정리

Player 아래에는 Plane1, Enemy 아래에는 Plane2가 들어간다.

이름만으로도 구분 가능하지만, 수업용으로는 다음처럼 이름을 바꿔도 좋다.

```text
PlayerVisual
EnemyVisual
```

### 4. 외형 전용 자식 구조 설명

학생들에게 다음 구조를 설명하면 좋다.

```text
Player 부모: 게임 기능 담당
Plane1 자식: 보이는 모습 담당
```

이 개념은 이후 캐릭터 외형 교체, 이펙트 부착, 총구 위치 조정에도 계속 사용된다.

## 최종 결론

이번 패치는 Player와 Enemy를 비행기 외형으로 바꾸는 중요한 시각적 개선 단계다.

기존 로직을 유지하면서 외형만 자식 프리팹으로 교체했기 때문에 구조가 안전하고, 초급자가 이해하기에도 좋다.
